Reasoning

Do this first for every release.

Canonical source

The current workflow intentionally uses the PPO ontology on GitHub main. The trait hierarchy is rebuilt from that source and versioned locally under reasoning/<version>/ppo.owl. 

python3 reasoning/refresh_traits.py

Generated artifacts

  • data/traits.csv
  • docs/traits.csv

Reasoning Sequence

Trait rebuild path

  1. 01
    Pull the current PPO ontology.

    Download the GitHub-hosted ppo.owl source used for the release.

  2. 02
    Snapshot the exact ontology version.

    Store the build input under a versioned directory in reasoning/.

  3. 03
    Regenerate the trait lookup.

    Create data/traits.csv and publish the matching Pages outputs.

  4. 04
    Review the semantic diff.

    Check new traits, renamed labels, and metadata before any ingest work begins.

Ingest

Structured loading, dry run first.

Release procedure

  1. Refresh the PPO-based trait mapping.
  2. Review ontology version, traits diff, and metadata.
  3. Prepare the dataset directory and optional transform.yaml.
  4. Run a dry ingest with loader.py --test.
  5. Resolve issues in loading_errors.csv.
  6. Run the real ingest.
  7. Backfill derived fields on the live index if needed.

Main loader command

python3 loader.py \
  --mode=<machine|in_situ|herbarium> \
  --test \
  --no-drop-existing \
  <data_dir>

The loader validates required fields from data/columns.csv, expands trait mappings through data/traits.csv, applies optional dataset-local transforms, and bulk indexes into Elasticsearch.
