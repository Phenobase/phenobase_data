python3 reasoning/refresh_traits.py

Data loading

After reasoning, prepare the source release as a dataset directory of `.csv` files. The loader reads field definitions from `data/columns.csv`, trait expansions from `data/traits.csv`, and an optional dataset-local `transform.yaml` for source-specific cleanup and trait normalization.

  1. Prepare a dataset directory containing one or more source `.csv` files.
  2. Add `transform.yaml` when the release needs field cleanup, case normalization, regex mapping, null handling, or trait remapping before validation.
  3. Run a dry load first. Test mode validates rows, checks duplicate `annotationID` values within each file, computes derived fields, and simulates create versus update counts without writing documents.
  4. Review `loading_errors.csv` for missing `annotationID`, empty or unmapped `trait`, duplicate IDs, and any strict-mode coercion failures.
  5. Fix the source files or the dataset transform rules, then rerun test mode until the release is clean enough to load.
  6. Run the real load. The loader recursively walks the dataset directory, indexes to `phenobase2`, and uses `annotationID` as the idempotent Elasticsearch document `_id`.
  7. Choose index behavior intentionally: keep the existing index for additive or update loads, or use `--drop-existing` when rebuilding the index from scratch.
  8. If needed, backfill `decadeStart` on the live index after loading.
python3 loader.py --mode=<machine|in_situ|herbarium> --test --no-drop-existing <data_dir>

During loading, the script derives `mappedTraits` from the reasoned trait hierarchy and derives `decadeStart` from `year` when that system field is present in the schema. Use `--strict` when you want coercion and validation problems to reject rows instead of being silently nulled. 

python3 loader.py --mode=<machine|in_situ|herbarium> --strict --no-drop-existing <data_dir>
python3 loader.py --mode=<machine|in_situ|herbarium> --drop-existing <data_dir>

transform.yaml

Place `transform.yaml` inside the dataset directory being loaded. It is optional and only applies to that release. Use it to normalize raw source values before datatype coercion and trait lookup.

Supported top-level keys:

  • `fields`: per-field transforms and field-level overrides.
  • `trait_mappings`: exact lowercase raw trait to canonical trait label remapping.
  • `null_values`: tokens treated as null across fields.
  • `coercions`: global parsing rules for boolean, date, integer, float, and text handling.

Supported per-field transform steps, applied in order:

  • `strip`
  • `case` with `lower`, `upper`, `title`, `capitalize_first`, or `scientific_name_standard`
  • `regex_sub` with `pattern`, optional `replacement`, and optional flags
  • `regex_map` with `pattern`, `to`, and optional flags
  • `null_if_in` with a list of values
  • `map` with exact value-to-value replacements
fields:
  scientificName:
    transforms:
      - op: strip
      - op: case
        rule: scientific_name_standard
  trait:
    transforms:
      - op: strip
      - op: case
        rule: lower

trait_mappings:
  breaking leaf buds: breaking leaf bud present

null_values: ["", "na", "n/a", "-"]
